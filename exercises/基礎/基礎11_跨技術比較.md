# 基礎 11 · 同一種血、七種技術

**難度**：★★ ｜ **預估時間**：1–1.5 個工作天 ｜ **對應集數**：B6、B11

## 背景與研究主題

Ding 等人（2020）做了一件教科書級的事：把同樣的 PBMC 用七種單細胞技術各定序一遍——10x v2、10x v3、Smart-seq2、Seq-Well、inDrops、Drop-seq、CEL-seq2。生物學被鎖死了，剩下的差異幾乎全是技術。這讓它成為 B11「該不該整合、整合掩蓋了什麼」最乾淨的教材：你可以先不整合，親眼看技術效應有多大；再整合，看它能救回什麼；最後追問——整合抹平的東西裡，有沒有其實是**真實的靈敏度差異**、而不是該被抹平的雜訊？這一題同時是 B6 的深化：不同技術的 nCount 根本不在同一個尺度上（有的甚至不是 UMI），normalization 能救什麼、不能救什麼，這裡看得最清楚。你的研究主題：

1. 不整合直接合併，七種技術在 UMAP 上分開得多嚴重？細胞是按型別聚還是按技術聚？
2. 各技術的每細胞基因偵測數、counts 分布差多少？哪些細胞型別在哪些技術下缺席或萎縮？
3. 按技術整合後，同型別跨技術對齊了嗎？各技術找出來的 marker 一致嗎？整合掩蓋了什麼？

## 資料集

- **SeuratData `pbmcsca`**：31,021 cells，7 種技術（10x v2/v3、Smart-seq2、Seq-Well、inDrops、Drop-seq、CEL-seq2）；原始資料為 GSE132044／Broad SCP424。
- 下載：R 內 `install.packages("SeuratData", repos="https://seurat.nygenome.org")` 後 `InstallData("pbmcsca")`、`LoadData("pbmcsca")`。
- 格式注意：技術別、作者的型別註解等都在 metadata，欄名以 `colnames(obj[[]])` 實際確認為準；作者註解欄留到對答案用。另注意 Smart-seq2 是全長、無 UMI 的技術，它的 counts 是 read 數，跟液滴技術的 UMI 數不在同一個物理尺度上。

## 任務

### 階段 A：不整合，直視技術效應（對應 B6、B11）

1. QC 後直接 merge（不整合）跑標準流程到 UMAP，按技術上色。描述你看到的：哪些技術自成大陸？哪些混在一起？同一型別（用 lineage marker 快查）被切成幾塊？
2. 量化各技術的靈敏度：per-cell nFeature 與 nCount 的 violin（按技術分組）、每技術的 median genes/cell 表。回答 B6 的問題：log-normalize 把每顆細胞除以自己的總量，為什麼仍救不了「10x v3 每顆測到的基因就是比 Drop-seq 多」這件事？normalization 修的是什麼、修不了什麼？
3. 把「技術效應的大小」跟你在基礎02 看過的「donor 效應」、基礎03 的「刺激效應」放在同一個心智標尺上排序，寫 3–5 句話。

### 階段 B：整合與型別盤點（對應 B11）

4. 按技術整合（七批資料，建議 Harmony 或 Seurat RPCA/reference-based anchors——記憶體較省；方法與參數三件事照規矩）。出整合後 UMAP：按技術、按分群各一張，評估混合程度。
5. 註解主要型別（PBMC marker 你已經很熟），再與作者的型別註解欄對答案。
6. 型別 × 技術盤點：做 celltype × method 的細胞數與比例交叉表。哪些型別在哪些技術下缺席或明顯萎縮？對每個缺席案例提出假說：是技術偵測不到（靈敏度／細胞大小偏好）、實驗流程丟掉了（分選、裂解）、還是細胞數太少純抽樣？

### 階段 C：marker 一致性與「整合掩蓋了什麼」（對應 B11、B6）

7. 挑 2–3 個主要型別，**按技術分開**各自做 FindMarkers（該型別 vs 其餘），比較各技術 top 20 marker 的重疊（upset plot 或重疊率表）。哪些 marker 七種技術都找得到（穩健核心）？哪些只在深測技術出現？
8. 寫 300–400 字整合決策短文，正面回答 B11：這份資料該整合嗎（答案幾乎是該——說出為什麼）；整合後你「看不見」了什麼（技術靈敏度差異、缺席型別的訊息）；如果有人拿七種技術的資料先整合再宣稱「某型別在某平台不存在」，錯在哪？

## 繳交物

1. 可重跑的 R 專案。
2. 圖：未整合 vs 整合後 UMAP（各按技術/型別上色）、per-tech nFeature/nCount violin、celltype × method 比例圖、marker 重疊比較圖（英文標籤）。
3. 分析筆記：參數三件事＋效應大小排序＋型別缺席假說清單。
4. 整合決策短文（300–400 字）。

## 自我檢核點

- [ ] 有先看過「不整合」的版本才整合，兩版 UMAP 都留檔
- [ ] 能具體說出 normalization 修得了與修不了的各一件事，且有圖佐證
- [ ] 整合方法的選擇與參數有三件事紀錄，混合程度有按技術上色的圖為證
- [ ] 每個「型別缺席」案例都有假說與證據方向，不是一句「技術差」帶過
- [ ] marker 一致性比較是按技術分開算的，短文能說出整合「掩蓋」的具體例子

## 提示（卡關再看）

<details><summary>提示 1：metadata 偵查</summary>
`LoadData("pbmcsca")` 後先 `colnames(pbmcsca[[]])` 與 `table()` 幾個候選欄，確認技術別欄與作者註解欄叫什麼、有幾個 level。物件版本不同欄名可能不同——親眼確認，別抄網路教學的欄名。
</details>

<details><summary>提示 2：整合記憶體吃緊</summary>
七批資料的 anchor 整合兩兩配對很貴。省法：Harmony（在 PCA 空間做，最省）、RPCA anchors、或 reference-based（挑 10x v3 這類深且大的批次當 reference）。選了哪條路、為什麼，寫進筆記——這本身就是 B11 的參數決策。
</details>

<details><summary>提示 3：Smart-seq2 的 counts 很怪</summary>
無 UMI 的 read counts 天生比 UMI 大一到兩個量級，且受基因長度影響。這不是 bug，是它的物理性質；比較分布時用 log 軸，解讀 nCount 時記得你在比的是兩種不同的東西——這正是階段 A 第 2 步要你回答的 B6 問題的一部分。
</details>

## 進階挑戰

- 用 kBET 或 LISI 這類混合度指標把「整合前後的技術混合程度」量化成數字，取代目測。
- 把 Smart-seq2 單獨拿掉重新整合一次，看整合結果與 marker 一致性變不變——「最不一樣的那批」對整合的拉扯有多大？
- 跨技術整合的終極版是進階30（HLCA 人類肺圖譜：107 人、14 個 datasets 的圖譜級整合）——先在七種技術的 PBMC 上想清楚「整合掩蓋什麼」，再去看圖譜等級的答案。
