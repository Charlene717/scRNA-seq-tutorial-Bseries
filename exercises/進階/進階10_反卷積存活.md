# 進階 10 · 單細胞反哺大隊列：反卷積與存活

**難度**：★★★ ｜ **預估時間**：1.5–2 個工作天 ｜ **對應集數**：B17 ｜ **資料集**：自建 signature + TCGA bulk（TCGAbiolinks；本題獨用）

## 背景與研究主題

單細胞資料告訴你「有哪些細胞」，但一個 cohort 幾十個病人撐不起存活分析；TCGA 有數百個病人的 bulk RNA-seq 與臨床存活，卻看不到細胞組成。B17 的核心動作就是把兩者接起來：**用單細胞註解建 signature，反卷積 bulk，估出每個 TCGA 病人的細胞比例，再問「這個比例跟活多久有沒有關係」**。這條鏈每一環都有踩雷點——而它也是投稿指南說的「新組合」型發表路徑的原型：題庫裡任何一張進階卡找到的細胞訊號，都可以沿本題的流程接上大隊列與臨床結局。你的研究主題：

1. 你的單細胞 signature 能不能穩定地反卷積出 TCGA bulk 的細胞組成？
2. 哪個（些）細胞型別的估計比例與整體存活（OS）相關——在誠實處理多重檢定之後？
3. 反卷積的比例沒有 ground truth——你拿什麼說服 reviewer 它不是雜訊？

## 資料集

- **單細胞端（自備）**：沿用你在前面題目完成的註解物件——做過**進階08**（GSE149614）配 **TCGA-LIHC**；做過**進階04**（GSE120575）配 **TCGA-SKCM**（擇一，配對要合理：組織要對得上）。
- **bulk 端**：`TCGAbiolinks`（Bioconductor）下載 TCGA-LIHC 或 TCGA-SKCM 的 RNA-seq counts + 臨床資料（每 cohort 數百樣本，含存活；需要網路與約 1–2 GB 暫存空間）。
- 注意：TCGA 樣本 barcode 要分清腫瘤/正常樣本（barcode 第 4 段 01 vs 11）。

## 真實數據關卡

TCGA 不是「下載就能用」的資料。照做並記錄：

1. **版本與平台選擇**：`GDCquery` 的每個參數都是決策——workflow.type 用 "STAR - Counts"、data release 版本記進筆記（不同 release 樣本數會變）。`GDCprepare` 回傳的 SummarizedExperiment 裡 `assays` 往往不只一個（counts、TPM 類的欄位並存）——你的反卷積工具要求哪種單位？查工具文件、選對 assay，選錯單位是本題最常見的全盤翻車點。
2. **基因命名對齊**：bulk 的 rownames 很可能是 **Ensembl ID（帶版本號後綴）**，你的單細胞物件是 symbol。對齊三連環：去掉 Ensembl 版本號 → ID 轉換（rowData 內建註解或 org.Hs.eg.db）→ 處理一對多與別名（同一 symbol 對到多個 Ensembl、舊別名對不上）。記錄對齊後**損失了多少基因、你的 signature 基因活下來幾個**——signature 基因掉太多，後面全是雜訊。
3. **臨床欄位清理**：存活時間是陷阱重災區。`vital_status`＋`days_to_death`／`days_to_last_follow_up` 要自己組成 time + event：死亡者用 days_to_death、存活者用 last follow-up 設 censored；小心 NA、0 或負值的時間、Alive 卻有 days_to_death 的矛盾列、同病人多筆記錄。每個被你丟掉或修正的病人都記下數量與理由——這一步錯了後面全錯。
4. **決策日誌**：開 `decisions.md`，凡是「資料逼你做的決定」（assay 選擇、ID 對齊損失、臨床清理規則、工具與單位）都記一筆：發現了什麼 → 選項 → 你選了什麼 → 理由。這是繳交物，也是論文 Methods 的草稿。

## 任務

### 階段 A：signature 與 bulk 兩端備料（B17）

1. 從你的單細胞物件建 signature matrix：決定用哪一層註解（太細會共線、太粗沒資訊——寫理由），每型別怎麼挑代表基因/細胞。紀錄型別 × 基因的最終矩陣規模。
2. 用 TCGAbiolinks 下載 bulk 與 clinical，過濾到 primary tumor 樣本，完成真實數據關卡的清理，整理出「表達矩陣 + 每病人 (time, event)」兩張乾淨的表。
3. 完成兩端基因命名對齊，損失數字進 decisions.md。

### 階段 B：反卷積與存活分析（B17）

4. 從 BisqueRNA / MuSiC / CIBERSORTx 擇一執行反卷積，**寫下選擇理由**（單細胞 reference 支援、授權與網頁限制、對輸入單位的假設）。產出病人 × 型別比例矩陣，先看 sanity：比例加總、明顯不合理的樣本。
5. **事先**挑 2–3 個有生物學理由的細胞型別（理由寫在跑存活之前——這是對抗 p-hacking 的第一道鎖），各以中位數切高低兩組，`survival::survfit` + `survminer::ggsurvplot` 畫 Kaplan-Meier，log-rank 檢定。
6. **多重檢定要落實**：你檢定了幾個型別、試了幾種切點？全部列出來，p 值校正或誠實標注 exploratory。**optimal cutpoint 警告**：「試了中位數、quartile、`surv_cutpoint` 最佳切點然後只報最顯著的那個」就是教科書級 p-hacking（B17 點名過）——要嘛事先鎖定切點，要嘛把試過的全部報出來。

### 階段 C：新組合發表路徑（發表導向；B17 踩雷區）

7. 可信度驗證至少兩個動作：(a) 換一個反卷積工具重跑，比較兩工具比例的相關性；(b) 已知 marker 的 bulk 表達（CD8A、CD68…）vs 對應型別估計比例的散點一致性；(c) signature 擾動（隨機拿掉 20% 基因）看比例穩不穩。
8. **新組合實作**：本題天生是投稿指南「新組合」切入點的引擎——把你在**任一進階題**找到的細胞訊號（進階03 的微環境亞群→SKCM、進階06 的 CAF signature→BRCA、進階08/09 的 T 細胞狀態→LIHC…）接進這條流程，看它與存活的關係。挑一個你真的做過的訊號跑通，並評估：這個「單細胞發現 × bulk 存活」的組合，原文獻做過嗎？
9. 寫「發表路徑」評估（見下節，300–500 字），核心是誠實回答：你的存活結論要降級成什麼強度的句子（「X 型別比例高的病人預後較差」還是「exploratory 分析中觀察到未校正的關聯」）？

## 繳交物

1. 可重跑的 R 專案（renv + set.seed(1234)、相對路徑；TCGA 下載腳本與快取分開）＋ `decisions.md` 決策日誌。
2. 圖：比例矩陣總覽（heatmap 或 stacked bar）、2–3 張 KM 曲線（含 risk table）、至少一張驗證圖（工具間相關/marker 一致性）（英文標籤）。
3. 分析筆記：每個參數三件事＋檢定次數與切點的完整清單。
4. 發表路徑評估（300–500 字）。

## 發表路徑

讀 `_從練習到投稿指南.md` 後回答：

- 你的「比例—存活」關聯屬於指南第二節的哪一類？它在多重檢定校正、換工具、signature 擾動之後還站著嗎？
- **驗證設計**：反卷積存活的天然驗證是**換一個獨立 bulk 隊列重跑同一條鏈**——另一個 TCGA cohort（組織要對得上你的 signature）或 ICGC 的對應癌種隊列（取得方式與隊列內容自行查證，這是本題的文獻功課）。方向一致才有資格寫進論文。
- **novelty 定位**：「免疫浸潤與存活」是超級紅海——PubMed 查你的型別在該癌種的預後文獻；你的新意通常不在「有關聯」，而在**訊號本身**（來自題庫某題的新亞群/新程式）與**組合**（那個訊號從沒被接到這個隊列過）。
- 若要成文：缺哪一塊（獨立隊列驗證／Cox 多變數校正年齡與 stage／機制故事）？純 in silico 的新組合，合理落點通常是計算/組學期刊層級——對照指南第四節評估。

## 提示（卡關再看）

<details><summary>提示 1：TCGAbiolinks 三步</summary>
`GDCquery(project="TCGA-LIHC", data.category="Transcriptome Profiling", data.type="Gene Expression Quantification", workflow.type="STAR - Counts")` → `GDCdownload` → `GDCprepare` 得 SummarizedExperiment；`colData` 就有臨床欄位，`rowData` 有基因註解（拿來做 Ensembl→symbol 對照很方便）。下載慢是正常的，快取好就別重抓。
</details>

<details><summary>提示 2：工具與輸入</summary>
BisqueRNA 與 MuSiC 都吃單細胞 reference（ExpressionSet/SingleCellExperiment），直接用你的物件與註解欄；CIBERSORTx 是網頁服務、要自己整理 signature 檔上傳。三者對 normalization 的假設不同——查各自文件，把「我餵了什麼單位」寫進 decisions.md。
</details>

<details><summary>提示 3：Ensembl 版本號</summary>
TCGA 的 rownames 形如 `ENSG00000141510.16`——先 `sub("\\..*", "", x)` 去版本號再對照。一個 symbol 對多個 Ensembl 時，常見做法是留表達量總和最高的那個，但無論選哪種去重規則，記進 decisions.md。
</details>

## 進階挑戰

- 用 Cox 比例風險模型取代二分法（比例當連續變數，加年齡/stage 當 covariate），比較結論是否穩健。
- 把兩個反卷積工具的比例各自接存活分析：結論一致嗎？不一致時你信哪個、為什麼？
- 對第二個 TCGA cohort 或 ICGC 隊列（自行查證）重跑全鏈，完成發表路徑要求的外部驗證。
