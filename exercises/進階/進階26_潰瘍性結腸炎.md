# 進階 26 · 發炎的腸道：潰瘍性結腸炎的三方重塑

**難度**：★★★ ｜ **預估時間**：2 個工作天 ｜ **對應集數**：B11、B12、B14、B19 ｜ **資料集**：Broad SCP259（本題獨用）

## 背景與研究主題

Smillie 等人（2019）的潰瘍性結腸炎（UC）圖譜是發炎性腸病單細胞研究的地標：18 位 UC 病人與 12 位健康者的結腸切片，總規模約 36 萬顆細胞，涵蓋上皮、免疫、基質三大區塊。UC 不是單一細胞型別的病——上皮屏障崩解、免疫細胞湧入、纖維母細胞轉成發炎表型，三方互相餵養。原論文的名場面之一是發炎相關纖維母細胞（inflammation-associated fibroblasts）：一個在健康腸道幾乎不存在、發炎時冒出來對免疫細胞大聲說話的基質亞群。這題是 B19 戰法在非腫瘤疾病上的完整演練：三個 compartment 分開精細註解、組成比較以病人為統計單位、通訊分析當偵探工具。你的研究主題：

1. 發炎 vs 健康，上皮／免疫／基質三方的組成各自怎麼變？哪些變化撐得起病人層級的統計？
2. 同一型細胞在發炎環境下的「狀態」改變（DE + 富集），與組成改變如何區分？
3. 三方之間的通訊重佈線：發炎組多出來的對話中，哪一條扛得住穩健性檢查、值得往發表推？

## 資料集

- **Broad Single Cell Portal SCP259**（scRNA-seq，~366,650 cells；SCP 頁面顯示 365,492——見真實數據關卡第 2 項；18 UC + 12 健康）。
- 格式：SCP 矩陣 + metadata（**下載需 Google 帳號登入**）；作者 GitHub 另有 Seurat 物件連結。
- **本題務必取子集**（資料集總覽有明訂）：36 萬顆細胞的全量分析不是本題目標，策略見真實數據關卡第 3 項。
- metadata 帶病人、健康狀態與作者細胞註解等欄位（實際欄位名以下載到的檔案為準）；作者註解留著對答案，階段 A 請自己註解。

## 真實數據關卡

真實資料在你跑第一行 Seurat 之前就開始出題。這一節照做並記錄：

1. **下載本身就是關卡**：SCP 不像 GEO 一個 wget 就完事——需登入、勾選檔案、有時走 bulk download 指令。把你實際走通的下載路徑（點了哪裡、用了什麼指令、抓了哪些檔）記下來；報告的 Data availability 要能讓別人照著重抓。下載後先 `ls -lh` 對檔案清單與大小，再決定讀法。
2. **數字對不上怎麼辦**：論文寫 ~366,650 顆，SCP 頁顯示 365,492 顆——差了一千多顆。這種出入在真實世界是常態（portal 版本更新、QC 標準微調、上傳批次差異），正確反應不是恐慌也不是無視，而是：記錄兩個數字與出處、載入後以 `dim()` 為準、在筆記裡寫下你對出入來源的合理猜測。**你引用規模時要寫清楚是哪個來源的數字。**
3. **36 萬顆的取子集策略**：先讀 metadata（它比矩陣小得多），看清楚病人 × 健康狀態 × 細胞數的分布再動手。可行策略：保留全部病人但每人下採樣固定細胞數、或選定病人子集（發炎與健康各留若干位）。無論哪種，規則與偏誤要寫清楚——每人下採樣保組成結構但稀釋稀有群；選病人省記憶體但 n 變小。載入即轉稀疏矩陣、子集完成立刻 `rm()` + `gc()`。
4. **決策日誌**：開 `decisions.md`，凡是「資料逼你做的決定」（下載路徑、數字出入、子集規則、metadata 欄位解讀）都記一筆：發現了什麼 → 選項 → 你選了什麼 → 理由。這是繳交物，也是論文 Methods 的草稿。

## 任務

### 階段 A：三方拆解與整合策略（B11 策略室）

1. 依你的子集規則載入資料，QC（每個閾值三件事）。先不整合跑一版 UMAP，觀察批次結構：30 位個體的腸道切片，哪些分離是病人效應、哪些可能是發炎狀態的生物訊號？
2. 決定整合範圍並執行（Harmony 或 anchors）：這裡沒有惡性細胞，B11 的答案跟腫瘤題不同——想清楚「發炎 vs 健康」是你要保留的生物差異還是要移除的批次，寫進 decisions.md。
3. 粗註解切出三大 compartment（上皮／免疫／基質），再各自精細註解：上皮至少分出吸收型與分泌型譜系、免疫至少分出 T/B/漿細胞/myeloid、基質至少分出纖維母細胞與內皮。與作者註解對答案，差異寫進筆記。

### 階段 B：組成與狀態的雙軌比較（B12）

4. 組成比較：每位病人算各型別比例，發炎 vs 健康分組畫圖（每個點是一個人）。檢定用 `speckle::propeller` 或 per-patient 比例 + Wilcoxon——**方法與基礎06 COVID 題完全同一套**，統計單位是病人不是細胞。報告至少 3 個明顯的組成變化，並檢查是否被單一病人拉動。
5. 狀態比較：挑 2 個型別（建議含纖維母細胞）做發炎 vs 健康的 pseudobulk DE + 富集，回答「這個型別是變多了、還是變了個樣、還是兩者都有」。
6. 找發炎相關纖維母細胞：你的基質亞群裡有沒有「幾乎只出現在發炎樣本」的群？用你自己的資料證據描述它，再跟原論文對照。

### 階段 C：三方通訊重佈線與發表評估（發表導向；B14、B19）

7. 對發炎組與健康組分別建 CellChat（或 CellPhoneDB）物件、跑比較流程：發炎組多出來的訊號集中在哪幾條軸（基質→免疫？上皮→免疫？）？挑一條深挖到 L-R pair 層級，回到表達層畫分病人的驗證圖（B14 踩雷區：通訊是從表達推論的，不是實測）。
8. 穩健性三連發：(a) 換一個符合同規則的病人/細胞子集重跑組成與通訊比較；(b) 通訊差異做組成混淆檢查（下採樣到相同組成重跑）；(c) 去掉貢獻最大的病人再跑。
9. 寫「發表路徑」評估（見下節，300–500 字）。

## 提示（卡關再看）

<details><summary>提示 1：SCP 下載</summary>
SCP259 頁面的 Download 分頁列出所有檔案；登入後可勾選單檔或用頁面產生的 curl bulk download 指令。矩陣與 metadata 檔名格式以頁面為準——先抓 metadata 類小檔看欄位，確認病人與健康狀態欄怎麼編碼，再決定矩陣抓哪些。作者 GitHub（原論文 Data availability 有連結）提供的 Seurat 物件是替代路線，但用它之前一樣要做真實數據關卡的檢查。
</details>

<details><summary>提示 2：compartment 分開處理</summary>
先在全體上粗分（EPCAM 上皮、PTPRC 免疫、其餘基質/內皮），再對各 compartment 分別重新 HVG → PCA → 分群——這是 B19「先切大塊、塊內精修」的標準動作。上皮與免疫混在同一空間分群時，發炎上皮的壓力反應基因常會蓋掉亞群結構。
</details>

<details><summary>提示 3：propeller 與雙軌解讀</summary>
`propeller(clusters, sample = patient, group = health_status)`。組成顯著但 DE 平淡＝「變多不變樣」；組成不變但 DE 強＝「變樣不變多」；兩者都有時，通訊差異的解讀要特別小心組成混淆——這正是階段 C 要你下採樣重跑的原因。
</details>
